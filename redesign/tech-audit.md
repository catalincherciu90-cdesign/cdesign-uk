## 2. _worker.js – Routing Logic & Demo System

### Core Functionality

**_worker.js is a Cloudflare Workers file** that handles:
- **Blog post rendering** (server-side HTML generation from structured data)
- **Demo site generation** (multiple layout templates)
- **Form submission handling**
- **Email notifications** (CRM deadline reminders)
- **URL routing for /demo/* paths**

### Demo Routing System (`/demo/...`)

The `/demo/*` pattern is used for **generated preview sites**. Structure:
```
/demo/{slug}               → renders demo homepage
/demo/{slug}/page-1        → renders inner page
/demo/{slug}/page-2        → etc.
```

**Key routes handled by _worker.js:**
- `POST /generate` → Create new demo from form data
- `POST /from-sketch` → Generate demo from AI sketch
- `GET /demo/*` → Serve rendered demo page (via generateMultiPageSite())

**Demo Features**:
- Each demo includes a footer `.demo-bar` with link back to `/programari.html` ("Get yours →")
- Demos use 4 layout templates: presentation website, online shop, blog/magazine, multi-page site
- Alert messages: "This is a demo — on a live site your message would be sent"

### No Permanent Redirects in _worker.js
The worker does **NOT contain 301 redirects for URL renames**. Redirects should be:
- Configured in `wrangler.toml` (Cloudflare routing rules)
- Added as rewrite rules in the worker's routing logic
- Implemented via `Response.redirect(url, 301)` if needed

**Security & Sanitization**:
- Blog content: HTML sanitization removes scripts, event handlers
- Form submissions: Escaped via `escHtml()` function

### SEO Redirect Strategy (301 Preserve Link Juice)

#### Phase 1: Setup (Before Renaming HTML Files)
1. **Add redirect rules in _worker.js** (or wrangler.toml):
   ```javascript
   // Example in _worker.js
   const redirects = {
     '/abonament-lunar': '/monthly-subscription',
     '/pachet-startup': '/startup-package',
     '/politica-confidentialitate': '/privacy-policy',
     '/web-design-afaceri-mici': '/web-design-small-business',
     '/web-design-auto': '/web-design-automotive',
     '/web-design-restaurante': '/web-design-restaurants',
     '/calculator-pret': '/price-calculator'
   };
   
   if (request.method === 'GET') {
     const url = new URL(request.url);
     if (redirects[url.pathname]) {
       return Response.redirect(
         url.origin + redirects[url.pathname],
         301
       );
     }
   }
   ```

2. **Update sitemap.xml** with new URLs:

## 5. CSS Structure – Common Design System Approach

### Current Architecture

**All CSS is inline in each HTML file** (no external stylesheet):
- Each page has a `<style>` block in `<head>`
- No separation of concerns (CSS not reusable across pages)
- Styles are duplicated across all 16 HTML files

**CSS Scope**:
- index.html: ~1,550 lines of CSS (including reset, variables, responsive design)
- Other pages: Similar block of CSS (likely identical or near-identical)
- globe-hero.html: Same base CSS + ~220 additional lines for globe-specific styles

### Key CSS Features to Preserve

1. **CSS Variables (--teal, --bg, etc.)**:
   ```css
   :root {
     --teal: #c9a96e;
     --teal-dk: #a8843d;
     --teal-lt: #dfc080;
     --bg: #ffffff;
     --text: #111111;
     /* ... 20+ more variables */
   }
   ```
   → Used throughout for theming; critical for rapid redesign

2. **Responsive Grid System**:
   - Desktop (1024px+): Multi-column layouts
   - Tablet (768px–1024px): 2-column or single-column
   - Mobile (480px–768px): Single-column stacked
   - Small mobile (<480px): Ultra-compact

3. **Component Classes**:
   - `.btn-primary`, `.btn-ghost`, `.btn-nav` — buttons with glow effects
   - `.hero`, `.hero-grid` — hero section with background overlay
   - `.services-grid`, `.portfolio-grid` — card-based layouts
   - `.testi-card`, `.port-card` — reusable card styles
   - `.container` — width constraint (max 1180px)

### Proposed CSS System for Redesign

#### Option A: Extract to External Stylesheet (RECOMMENDED)
1. **Create `/design-system.css`**:
   - Consolidate all base CSS from index.html
   - Extract variables, resets, responsive breakpoints
   - Include all utility classes (.btn-*, .hero-*, etc.)
   - Scope component styles with meaningful class names

2. **Link in all HTML files**:
   ```html
   <link rel="stylesheet" href="/design-system.css">
   ```

3. **Keep page-specific overrides inline** (if minimal):
   - Unique hero imagery for each city page
   - Custom color accents per industry page
   - Demo-specific styles for globe-hero.html

**Benefits**:
- Single source of truth for design
- Easier to maintain and test redesign
- Reduces file size per page (gzip compression)
- Faster updates across all pages

#### Option B: Component CSS Files (ADVANCED)
If preparing for long-term scalability:
```
/css/
  ├── reset.css          (normalize)
  ├── variables.css      (CSS custom properties)
  ├── typography.css     (fonts, heading, text)
  ├── layout.css         (container, grid, flex)
  ├── components/
  │   ├── nav.css
  │   ├── buttons.css
  │   ├── cards.css
  │   ├── hero.css
  │   ├── forms.css
  │   └── footer.css
  └── responsive.css     (media queries)
```
Each file imports via:
```html
<link rel="stylesheet" href="/css/design-system.css"> <!-- imports all -->
```

### Current CSS Duplication Issue

Every HTML file contains ~1,500 lines of CSS. For 16 pages:
- **Total size**: ~24 KB per page × 16 = **~384 KB** of duplicated CSS
- **With extraction**: ~24 KB + ~0.5 KB overhead per page = **~32 KB total** (90% reduction)

### Redesign Workflow Using Design System

1. **Update `/design-system.css`** (or Option B structure)
2. **Test on one page** (e.g., index.html)
3. **Roll out to all pages** by swapping CSS file
4. **Override variables as needed**:
   ```css
   /* In page-specific <style> block or via root override */
   :root {
     --teal: #00c8b4;  /* new primary color */
     --hero-bg: url(/new-hero.jpg);
   }
   ```

### Responsive Breakpoints (Preserve These)
```css
@media(max-width:1024px) { /* Tablet landscape */ }
@media(max-width:768px)  { /* Tablet portrait */ }
@media(max-width:480px)  { /* Mobile */ }
@media(max-width:380px)  { /* Small mobile */ }
```
